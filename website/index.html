How it works

Five composable stages — the same loop every SIEM (Splunk, Sentinel, Wazuh, ELK) implements. Rebuilt from scratch so the internals are visible.

1

Collect

Batch read a file or tail it like tail -f. Sources: Linux auth.log, nginx access log, Cowrie honeypot JSON.

→
2

Parse

Regex & JSON parsers normalise every event to an ECS-flavoured envelope: timestamp, source_ip, event_type, user.

→
3

Detect

YAML rule engine with four rule types: threshold, distinct_users, conditional, field_match. Sliding windows + cooldowns.

→
4

Enrich

AbuseIPDB reputation lookup with an SQLite cache — respects the 1,000-req/day free tier.

→
5

Alert

Console (Rich), Slack Block Kit, Discord embeds, JSONL log for the dashboard.

Sample incident — full compromise in 90 seconds

Running the pipeline against the bundled sample logs produces this 4-alert kill chain — a realistic SOC narrative.

  1. 02:14:08
    HIGH ssh_bruteforce · T1110.001

    203.0.113.42 triggered 5 failed SSH logins in the first 10 seconds of a 20-attempt burst.

  2. 02:14:45
    CRITICAL successful_bruteforce · T1110 + T1078

    Same IP successfully authenticated as root after 20 failures — attacker is in.

  3. 02:15:30
    HIGH new_user_after_login · T1136.001

    useradd svcbackup UID 0 — persistence via backdoor account.

  4. 02:22–02:26
    HIGH password_spraying · T1110.003

    Separate IP 198.51.100.17 sprayed 13 distinct usernames — different attacker, different technique.

~35 interleaved log lines → 4 prioritised alerts, each tagged with a MITRE technique. That's the value a SIEM adds every day.

Run it in 60 seconds

$ git clone https://github.com/akashjambulkar2-cyber/mini-siem
$ cd mini-siem
$ cp .env.example .env       # (optional) add ABUSEIPDB_API_KEY / SLACK_WEBHOOK_URL
$ docker compose up --build  # pipeline + dashboard on :8501

$ # or natively:
$ pip install -r requirements.txt
$ python -m src.main --input data/samples/auth.log --source ssh --no-enrich
$ streamlit run src/dashboard/app.py

Safe by default: bundled samples use RFC-5737 TEST-NET IPs. No secrets committed. Honeypot exposure only on isolated VMs.
